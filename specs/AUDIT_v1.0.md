# Аудит wanderers-master-specs-v1.0 (552 файла, 33 этапа)

Дата: 2026-10-06
Аудиторская база: `master spec.md` v2.0 (Solo Dev & AI-Native Edition) — единственный авторитетный источник.
Критерии: (а) геймдизайн-ценность, (б) реализуемость одним разработчиком с нейросетями, (в) соответствие HARD BLOCKS HB-01..HB-08.

## Общий диагноз v1.0

1. **Спек-справawl**: 31 нумерованный этап + 2 приложения, по 10-20 документов на этап. Большинство документов — «как должно быть хорошо», а не контракты реализации. Чтение и поддержка этого корпуса само по себе — полный рабочий день, недостижимый для соло-разработчика.
2. **Прямые нарушения будущих HARD BLOCKS**:
   - `21_faction_simulation`, `22_npc_simulation`, `26_world_simulation`, `27_economic_rpg` — симуляции фракций, индивидуальная память NPC, мировой тик, динамическая экономика. Нарушают HB-02 (динамический спрос/предложение), HB-03 (память каждого NPC), HB-06 (система влияет на >3 систем). Это самые дорогие в реализации и балансировке части с наименьшей видимой отдачей.
   - `24_systemic_quests` с динамической генерацией квестов — HB-04 (эмерджентная генерация → софтлоки).
   - Глубоко вложенные модели состояния (фракция→подфракция→лидер→настроение) — HB-01.
3. **Дублирование**: этапы 17→30 по сути переписывают друг друга с нарастающей сложностью (foundation → agency → skills → equipment → factions → npc → dialogue → quests → exploration → world → economy → density → story rewrite → polish). Каждый этап добавляет «interaction matrix» к предыдущим — комбинаторный взрыв.
4. **Позитив**: геймдизайн-интуиции v1.0 верные (информация как геймплей, failure forward, agency, конвертируемые знания). Они полностью перенесены в master spec v2.0 в упрощённом виде. Творческий канон (лор, граф истории, миссии) системными спеками не покрывается и сохраняется.

## Как пользоваться дальше

1. Системные решения — только из `master spec.md`. Противоречие с narrative/-каноном в части систем → побеждает master spec.
2. Сюжет, термины, миссии — из `narrative/`. При адаптации миссий под v2.0 переписывать по схемам §16 (quest/dialogue/item).
3. Всё удалённое остаётся в git-истории (коммит `fa29994`), восстановимо при необходимости.
